ABAC Policy Engine
Жоба тақырыбы: №14 --- ABAC саясат қозғалтқышы
Атауы: Attribute-Based Access Control Policy Engine
Бағдарламалау тілі: Java
Жоба түрі: Қол жеткізуді басқару және ақпараттық қауіпсіздік
Орындаушы: Реймқұл Ақерке
1. Research --- жоба туралы зерттеу
1.1. ABAC дегеніміз не?
ABAC (Attribute-Based Access Control) --- пайдаланушыға жүйедегі
ресурсқа қол жеткізу құқығын әртүрлі атрибуттарға сүйене отырып беретін
қол жеткізуді басқару моделі.

ABAC жүйесі тек пайдаланушының рөлін ғана емес, сұраныстың басқа да
сипаттамаларын ескереді. Мысалы, пайдаланушының бөлімі, сұралатын
құжаттың түрі, орындалатын әрекет, уақыт немесе орналасқан жері
тексерілуі мүмкін.
1.2. Жобаның мақсаты
Java тілінде JSON форматында сақталған саясат ережелерін оқып,
пайдаланушының, ресурстың, әрекеттің және ортаның атрибуттарын
тексеретін ABAC саясат қозғалтқышын әзірлеу. Тексеру нәтижесінде жүйе
қол жеткізуге рұқсат береді немесе тыйым салады.
1.3. Жобаның өзектілігі
Ақпараттық жүйелерде пайдаланушылардың деректерге қол жеткізу құқықтарын
қауіпсіз және икемді басқару маңызды. Тек рөлге негізделген басқару
кейбір күрделі жағдайларды қамти алмайды. Мысалы, бірдей рөлдегі екі
қызметкердің құжатқа қол жеткізу құқығы олардың бөлімдеріне немесе
сұраныс уақытына байланысты әртүрлі болуы мүмкін.

ABAC осы шарттарды саясат ережелері арқылы басқаруға мүмкіндік береді.
Ережелерді JSON файлында сақтау оларды негізгі бағдарламалық кодтан
бөлек басқаруға жағдай жасайды.
1.4. ABAC моделінің негізгі құрамдас бөліктері
  Құрамдас бөлік   Түсіндірме                      Мысал
  Subject          Сұраныс жіберетін пайдаланушы   role = teacher
Resource         Қол жеткізілетін ресурс         type = document
Action           Орындалатын әрекет              read, write, delete
Environment      Сұраныс орындалатын орта        уақыт, бөлім, IP
1.5. Жобаның жұмыс істеу принципі
1. Жүйе JSON файлынан саясат ережелерін оқиды.
2. Пайдаланушы сұраныс жібереді.
3. Сұраныс пайдаланушы, ресурс, әрекет және орта атрибуттарынан тұрады.
4. ABAC қозғалтқышы сұраныс атрибуттарын саясат шарттарымен
   салыстырады.
5. Шарттарға сәйкес саясат табылса, жүйе тиісті шешім шығарады.
6. Рұқсат беретін саясат табылмаса, әдепкі шешім DENY болады.
7. Шешімнің нәтижесі мен себебі көрсетіледі.

1.6. Жобаның міндеттері
- ABAC моделінің теориялық негіздерін зерттеу.
- Subject, Resource, Action және Environment атрибуттарын сипаттау.
- JSON форматында саясат ережелерін құру.
- JSON файлынан саясаттарды жүктеу механизмін әзірлеу.
- Ереже шарттарын тексеретін логика жасау.
- PERMIT және DENY шешімдерін шығару.
- Қате және бос деректерді қауіпсіз өңдеу.
- JUnit 5 көмегімен кемінде 10 тест әзірлеу.
- GitHub талаптарына сәйкес құжаттама мен CI дайындау.

6. Криптография
Жобаға криптографиялық функция қажет болған жағдайда өз алгоритмімізді
ойлап таппаймыз. Java платформасының стандартты JCA (Java Cryptography
Architecture) құралдарын қолданамыз.

Қолданылуы мүмкін стандартты құралдар:

  Құрал                Мақсаты
  MessageDigest      SHA-256 хэшін есептеу
Signature          Электрондық қолтаңбаны тексеру және жасау
KeyPairGenerator   Ашық және жабық кілт жұбын генерациялау
SecureRandom       Қауіпсіз кездейсоқ мәндер жасау

ABAC жобасында бұл құралдарды, мысалы, саясат файлының тұтастығын
тексеру немесе саясат конфигурациясына қолтаңба қою үшін пайдалануға
болады. Криптографиялық кілттер репозиторийге салынбайды.
7. Тестілеу --- JUnit 5

  №    Тест сценарийі                          Күтілетін нәтиже
  1    Рұқсат беретін дұрыс сұраныс            PERMIT

8. GitHub Actions --- CI
GitHub Actions арқылы кодты автоматты түрде жинақтау және тестілеу
ұйымдастырылады.

Ұсынылатын файл: .github/workflows/ci.yml
name: Java CI

on:
  push:
  pull_request:

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Set up JDK 17
        uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: '17'
          cache: maven

      - name: Build and test
        run: mvn --batch-mode clean verify
Бұл workflow репозиторийге код жіберілгенде немесе Pull Request
ашылғанда іске қосылады. Ол жобаны жинақтап, тесттерді орындайды.
